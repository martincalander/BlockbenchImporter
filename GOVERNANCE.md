# Governance

Martin Calander maintains this project and has the final say on scope, releases, repository access, and security fixes.

Most decisions happen in issues and pull requests. For a large change, please explain:

- how Blockbench stores the feature;
- what Unity should generate;
- what may change for existing models;
- how it can be tested.

The aim is to reach agreement in public. Security work may stay private until a fix is released.

Version tags, `package.json`, and `CHANGELOG.md` should always agree. Patch releases fix bugs, minor releases add compatible features, and major releases may change defaults, hierarchy, APIs, or the minimum Unity version.

If Martin can no longer maintain the project, he may hand it to another maintainer or archive it clearly. Apache 2.0 still allows anyone to fork it, subject to the license and NOTICE terms.
