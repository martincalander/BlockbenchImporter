# Governance

Unity Blockbench Importer is a maintainer-led open-source project.

## Roles

- **Maintainer:** Martin Calander has final responsibility for roadmap, releases, security coordination, repository access, licensing stewardship, and project scope.
- **Contributors:** anyone who submits issues, documentation, tests, code, design feedback, or other accepted work.

Consistent contributors may be invited to review or triage changes. Repository permissions do not transfer copyright ownership or release authority.

## Decisions

Routine decisions are made through issue and pull-request discussion. Broad changes should begin with a public proposal that explains the Blockbench semantics, Unity representation, compatibility risks, test strategy, and migration impact.

The maintainer seeks technical consensus but retains the final decision when consensus is not possible. Security fixes and embargoed disclosures may be handled privately until release.

## Releases

Releases use semantic versioning where practical:

- Patch releases fix defects without intentionally changing supported behavior.
- Minor releases add backward-compatible importer features or settings.
- Major releases may change defaults, generated hierarchy, public APIs, or supported Unity versions.

Tags, `package.json`, and `CHANGELOG.md` must agree. Release archives and SHA-256 checksums are generated by GitHub Actions from tags.

## Project continuity

If the maintainer can no longer sustain the project, they may appoint a successor or archive the repository with a clear status notice. Forks remain permitted under Apache 2.0 and must preserve applicable license and NOTICE requirements.
